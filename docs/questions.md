# 質問の作り方

日本語 | [English](en/questions.md)

質問は、型と、選択肢ごとの説明で作ります。説明は文のほか、画像や音でもかまいません。Shiken は説明の埋め込みベクトルと項目の埋め込みベクトルの近さでスコアリングするので、回答 0 件のときの当たり方は説明の作り方で大きく変わります。料理の「辛い」を当てる質問では、説明文の書き方によって AUROC が 0.60 から 0.92 まで変わりました。

## 3 つの型

### 段階（Score）

順序のある段階のどこに当たるかを聞きます。答えは各段階の確率と、段階の値の期待値です。

```python
Score([(1, "辛さのない優しい味の料理の写真"),
       (5, "唐辛子やラー油がたっぷり入った激辛料理の写真")])
```

段階は両端の 2 つだけでも、間を埋めて 5 つにしてもかまいません。2 択の回答でパーソナライズできるのは、この型とはい／いいえの型です。

### 選択（Choice）

選択肢から 1 つを選びます。答えは選択肢ごとの確率です。

```python
Choice({"和食": "和食の料理の写真", "中華": "中華料理の写真", "イタリアン": "イタリア料理の写真"})
```

選択の型は、今は 2 択の回答でパーソナライズできません（素の価値尺度だけで答えます）。

### はい／いいえ（Noul）

当てはまるかどうかを聞きます。答えは当てはまる確率です。

```python
Noul("スープや汁物の料理の写真", contrast="汁気のない料理の写真")
Noul("眼鏡をかけた人の顔写真", neutral="人の顔写真")
```

`contrast`（当てはまらない状態の説明）を書くと、2 つの説明の 2 択として解きます。書かない場合は、`neutral` に渡した分野の名詞だけの中立の文（「人の顔写真」など）との差で測ります。`neutral` も無い場合は、比較用の集合での平均との差で測ります（パーソナライズするときに概念の語を渡していれば、その名詞を中立の文に使います）。眼鏡や地図のような「有るか無いか」の質問では、「眼鏡をかけていない人」のような否定の文を書くより、書かずに中立の文と比べる方がよく当たりました。

## 文で説明する

- **単語ではなく、当てはまる項目の様子を書く。** 「辛い」より「唐辛子やラー油がたっぷり入った激辛料理の写真」の方が当たります。埋め込みモデルは、項目そのものを説明した文との近さを測るのが得意です。
- **色の語に気をつける。** 「真っ赤な」のように色を書くと、その色の別のもの（辛さと関係ないレッドベルベットケーキなど）が上がります。
- **言い回しを複数書いて平均できる。** 説明の代わりに文のタプルを渡すと、埋め込みベクトルを平均します。日本語と英語を並べると、良い方の言語を超えることはありませんが、悪い方に外れることは避けられました。
- **料理名のように固有の名前を区別する質問は、英語の方が当たる。** Food-101 の 101 クラスの分類では、英語の料理名で top-1 0.83、日本語で 0.67〜0.70 でした（海外の料理をカタカナにした名前は日本語に不利でした）。印象や性質の質問では、日本語と英語の差に一貫した傾向はありませんでした。

## 画像や音で説明する

> 写真で曲を並べる使い方だけを、デモのデータで試しました（下の「写真で曲を並べた結果」）。ほかの組み合わせは、仕組みの上でできることを書いたもので、どこまで当たるかはまだ確かめていません。

説明には、ファイルや埋め込みベクトルも渡せます。

```python
from shiken import File

# 写真 1 枚に合う曲を並べる
Noul(File("sunset.jpg"))

# 「こういう感じの料理」を、例の写真で段階にする
Score([(1, (File("plain1.jpg"), File("plain2.jpg"), File("plain3.jpg"))),
       (5, (File("great1.jpg"), File("great2.jpg"), File("great3.jpg")))])
```

仕組みの上で分かっている注意が 2 つあります。

- **1 つの質問の中では、説明の種類をそろえる。** マルチモーダル埋め込みモデルの空間では、画像は画像どうし、文は文どうしで固まる傾向があります（modality gap。CLIP などで知られています）。段階 1 を文、段階 5 を画像にすると、2 つの差の向きに「画像らしさ」そのものが混ざり、項目が質問の中身ではなく画像らしさで並んでしまいます。一方、写真 1 枚で曲を並べるように、説明が 1 つで項目が 1 種類なら、この偏りはどの項目にも同じだけ足されるので、並び順は変わりません。同じ理由で、はい／いいえの質問の説明が画像や音のときは、中立の文との差ではなく、比較用の集合での平均との差で測ります。
- **例の画像は 1 枚より数枚。** 画像で画像を評価すると、色や構図が似ているかどうかの影響が強く出ます。同じ段階の例を数枚渡して平均すると、例どうしに共通する性質が残りやすくなるはずです。

### 写真で曲を並べた結果

デモの風景の写真 1 枚を質問（`Noul(File(写真))`、説明 1 つで中立の文なし）にして、デモの「世界の音楽」110 曲を回答 0 件で並べました。曲の BPM と、文の質問「落ち着く」「ノれる」での並びとの順位相関で確かめています（EmbeddingGemma 2）。

| 質問にした写真 | 「落ち着く」との相関 | BPM との相関 | 上位 10 曲の平均 BPM（全体は 108） |
| :-- | --: | --: | --: |
| 霧の朝の湖畔のキャビン | +0.67 | −0.31 | 90 |
| 穏やかな朝の氷河湖 | +0.79 | −0.33 | 86 |
| 雨の夜の大都会の交差点 | −0.32 | +0.33 | 131 |
| 夏の夜のアジアの夜市 | −0.21 | +0.32 | 114 |
| 晴れた南の島のビーチ | +0.40 | −0.04 | 101 |
| 夕暮れの溶岩の火山 | +0.43 | −0.09 | 103 |

静かな写真では遅く穏やかな曲が、夜の都会や夜市の写真では速く激しい曲が上に来ました。一方、どの写真でも上に来やすい曲（アンビエントや、ピアノで始まるダブステップ）があり、ビーチや火山のように雰囲気が中間の写真では並びがはっきりしませんでした。

雰囲気の違う 2 枚を当てはまる側と当てはまらない側（`Noul(File("湖畔.jpg"), contrast=File("交差点.jpg"))`）にすると、「落ち着く」との相関が +0.77、BPM との相関が −0.52 と、写真 1 枚より強く出ました。写真で曲を選ぶなら、対になる写真を添える形を勧めます。

## 素の価値尺度では当たらないもの

素の価値尺度は空間の中の 1 本の向きなので、次のような評価は苦手です。

- **数を数える評価。** アプリの画面の「情報量の多さ」と実際の要素の数の順位相関は 0.07〜0.24 でした。
- **見た目や音から推しにくい印象。** 音楽の「明るさ」と人がつけた感情価の順位相関は 0.52 でした。CLIP でも、「重そう」「フォーマル」のような印象語は人の評価と相関しなかったと報告されています（柴田 2026）。
- **確率の値そのもの。** 温度を正解つきのデータで決めない限り、意味があるのは並び順です。

こうした質問でも、2 択の回答でパーソナライズはできます。ただし、価値尺度が 1 本の向きであることは変わらないので、合わせられる程度にも限りがあります。
