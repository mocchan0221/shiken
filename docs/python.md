日本語 | [English](en/python.md)

## インストール

```bash
pip install shiken            # スコアリングとパーソナライズ（numpy だけ）
pip install "shiken[eg2]"     # EmbeddingGemma 2 で埋め込みベクトルも計算する（PyTorch が入る）
```

最初の公開では PyPI に出さず、`pip install git+https://github.com/<所有者>/shiken` で配る予定です。

## 埋め込みベクトルを用意する

Shiken の本体は埋め込みベクトルを計算しません。データセットの埋め込みベクトル（`(項目数, 次元)` の numpy 配列、各行の長さを 1 にしたもの）と、質問の説明を埋め込む方法を渡します。

説明を埋め込む方法は、次の形を持つオブジェクト（エンコーダ）で渡します。

```python
class Encoder(Protocol):
    name: str                                         # 価値尺度ファイルに記録する名前。違えば別の空間とみなす
    def embed_texts(self, texts: list[str]) -> np.ndarray: ...
    def embed_files(self, paths: list[str]) -> np.ndarray: ...   # 画像や音を説明に使うときだけ要る
    def info(self) -> dict: ...                                  # 任意。価値尺度ファイルに書く、版などの詳細
```

どのメソッドも、長さ 1 に正規化したベクトルを返します。

EmbeddingGemma 2 を使う場合は、付属のエンコーダがデータセットの埋め込みベクトルも計算します。

```python
from shiken.encoders import EmbeddingGemma2

enc = EmbeddingGemma2()                      # GPU があれば使う。結果は ~/.cache/shiken に保存して再利用する
items = enc.embed_files(["a.jpg", "b.jpg"])  # 画像・音声・動画
docs = enc.embed_documents(["商品の説明文", ...])  # 文をデータセットの項目として埋め込む
```

画像だけを扱うなら `EmbeddingGemma2(modalities=("image",))` とすると、音声の部分を読み込まずに済みます。

ほかのモデルを使う場合は、上の形のクラスを自分で書きます（[埋め込みモデル](embedding-models.md)）。データセットと質問の説明は、同じモデルの同じ空間に埋め込む必要があります。

## 素の価値尺度で答える

回答を集めずに、型の決まった答えだけがほしい場合は `shiken.ask` を使います。

```python
from shiken import Score, Noul

answers = shiken.ask(items, {
    "辛そう度": Score([(1, "辛さのない優しい味の料理の写真"), (5, "唐辛子やラー油がたっぷり入った激辛料理の写真")]),
    "汁物": Noul("スープや汁物の料理の写真", contrast="汁気のない料理の写真"),
}, encoder=enc)

answers[0]["辛そう度"].score          # 段階の期待値（例: 2.3）
answers[0]["汁物"].probability        # 当てはまる確率
```

各答えには、確率のほかに確信度（1 − 正規化したエントロピー）と、1 位と 2 位の確率の差が付きます。質問の作り方は [質問の作り方](questions.md) にあります。

## 2 択でパーソナライズする

```python
taste = shiken.Taste(
    question=Score([(1, "全然美味しくなさそうな料理の写真"), (5, "最高に美味しそうな料理の写真")]),
    items=items,                    # データセットの埋め込みベクトル
    ids=paths,                      # 項目の名前（個別の加減点と価値尺度ファイルに使う）
    encoder=enc,
    concepts=shiken.concepts.FOOD,  # 概念の語。省くと埋め込みベクトルそのものだけでずれを表す
)
```

| 引数 | 意味 |
| :-- | :-- |
| `question` | 段階（Score）かはい／いいえ（Noul）の質問 |
| `items`, `ids` | データセットの埋め込みベクトルと、項目の名前 |
| `encoder` | 質問の説明と概念の語を埋め込むエンコーダ |
| `concepts` | 概念の語のリスト。付属のもの（料理・絵画・画面・写真・顔・音楽）か、`shiken.Concepts(words=[...], noun="服の写真")` で自作したもの |
| `reference` | 比較用の集合。省くと `items` を使う |

### 出題と回答

```python
a, b = taste.next_pair()        # 次に聞く組（項目の名前）
p = taste.predict(a, b)         # 答える前の予想: a が選ばれる確率
taste.answer(a, b, prefer=a)    # a が選ばれた。prefer=None なら「同じくらい」
taste.hit_rate(last=10)         # 直近 10 問の予想の的中率
```

`answer` は回答を記録して補正し直し、答える前の予想を返します。個別の加減点の大きさは 10 問ごとに選び直します（毎回選ぶと補正の時間が約 5 倍になるため）。データセットが 165 件のとき、1 問あたりの補正と次の組の選択は CPU で 0.3〜0.4 秒でした。

### スコアリング

```python
taste.rank()                    # 項目の名前を、パーソナライズしたスコアの高い順に
mean, var = taste.scores()      # データセットの各項目のスコアと、その不確かさ
mean, var = taste.scores(other_items)   # データセットにない項目（個別の加減点は使わない）
```

スコアは相対値で、データセットの中での比較にだけ意味があります。段階の質問でも、パーソナライズしたあとのスコアは段階の値（1〜5）には戻しません。

### 価値尺度を言葉にする

```python
taste.explain(top=6)
# {"up": [("炒め物", 0.41), ("中華料理", 0.38), ("辛い", 0.35)], "down": [("洋菓子", -0.44), ...]}
```

比較用の集合の各項目について、補正で動いた分と各語らしさの相関を返します（[仕組み](concepts.md#補正の中身の表示)）。自分の好みが「辛い」寄りなのか「ヘルシー」寄りなのかが、語の並びで分かります。

| 引数 | 意味 |
| :-- | :-- |
| `words` | 照らし合わせる語。省くと `concepts` の語（料理なら 98 語）。`shiken.words.large("food")`（色・質感・光・構図・雰囲気などを足した広い辞書。料理なら約 400 語）や、`shiken.Concepts(words=[...], noun="料理の写真")` で自作した語も渡せる |
| `part` | `"correction"`（既定）は素の価値尺度からのずれだけ、`"all"` は価値尺度全体 |

価値尺度ファイルだけからでも言葉にできます。データセットが無いときは、価値尺度ファイルに入っている答えた項目の埋め込みベクトルを比較用の集合の代わりに使います（100 問なら約 200 項目）。

```python
enc = EmbeddingGemma2(modalities=())           # 語を埋め込むだけなので、画像や音の部分は読み込まない
shiken.explain("my_taste.json", encoder=enc, words=shiken.words.large("food"))
```

著者の「美味しそう」の価値尺度ファイル（101 問）では、高く見る側に「具だくさんの・唐辛子の多い・麻婆豆腐・辛い」、低く見る側に「滑らかな・アイスクリーム・淡い色の」が並びました。

### 保存と読み込み

```python
taste.save("my_taste.json")
taste = shiken.Taste.load("my_taste.json", items=items, ids=paths, encoder=enc)
```

読み込むと、保存した回答から補正し直します（個別の加減点の大きさもこのとき選び直します）。データセット（`items`）を省くと、価値尺度ファイルに入っている答えた項目をデータセットにします。読み込む側のデータセットが保存した側と違ってもかまいません。価値尺度ファイルに答えた項目の埋め込みベクトルが入っているので、データセットにない項目への回答も補正に使えます。埋め込みモデルの名前が違う場合は、保存した埋め込みベクトルを使わず、読み込む側のデータセットにある項目への回答だけで補正します。使えなかった回答の数は `taste.skipped` に入ります。形式は [価値尺度ファイルの形式](profile-format.md) にあります。

デモで答えて保存した価値尺度ファイルを、手元の別のデータセットに当てはめる作例が 2 つあります。どちらも、使うデータを実行時に取ってきます。

- `examples/aozora_classics.py`: デモの小説のあらすじで教えた好みで、青空文庫の名作（あらすじは Wikipedia）を並べる
- `examples/met_paintings.py`: デモの絵で教えた好みで、メトロポリタン美術館の所蔵品（パブリックドメイン、画像は CC0）を並べる

文の項目は、答えたときと同じ形にそろえて埋め込むと結果が安定します。デモのあらすじは「1 行目が題、2 行目からがあらすじ」です。著者の価値尺度ファイル（50 問）で試すと、題を付けずにあらすじだけを埋め込んだ場合は、題を付けた場合と比べて並びの相関が 0.94、上位 10 件のうち重なるのは 7 件でした。

### 1 本のベクトルにする

```python
w, c = taste.weight_vector()    # スコア = w · s + c
```

価値尺度を、埋め込みベクトルと同じ次元のベクトル 1 本（価値尺度ベクトル）にします。ベクトル検索のデータベースで並べ替えたいときに使えます。個別の加減点は含みません。

## 予定している機能

- **他人の価値尺度ファイルから始める。** 料理人の価値尺度ファイルを出発点にして、自分の回答で補正する。
- **選択の型でのパーソナライズ。**
- **はい／いいえで答える回答**（2 択の代わりに、1 つの項目に「当てはまる」「当てはまらない」で答える）。

ブラウザ版のためのパックを作る `export_pack` は [JavaScript で使う](javascript.md) にあります。
